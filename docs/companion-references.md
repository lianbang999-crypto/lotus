# 人机恋 / 陪伴类项目调研：莲花借鉴什么，不借鉴什么

调研日期：2026-09-15。目标是「莲花只有一个聊天入口」这一前提下，从 GitHub 上活跃的 AI 陪伴 / 人机恋项目里找**让人愿意每天回来聊**的交互细节。本次只读官方 README、文档与公开截图，没有安装或复用任何项目代码。

## 一句话结论

这些项目的黏性并不来自角色立绘或语音，而来自三件更便宜的事：**它知道现在几点、它记得你昨天说过什么、它不会把你的话弄丢**。这三件莲花都能在现有 Cloudflare Agent + 一个聊天入口的架构里做到，本轮已落地。至于主动私聊、情绪值、亲密度等级、角色养成，与「净土伴修、不施加愧疚」的产品边界冲突，明确不做。

## 从中提炼的五条原则

1. **知道现在几点，比知道你叫什么更重要。** KouriChat 的时间感知、Everthine 的早安消息、Yuralume 的作息，本质都是「对方活在和我同一条时间线上」。莲花做法：按北京时段变化的问候（夜深了 / 早安 / 午安 / 下午好 / 晚上好）、起手句顺序随时段调整（早上先功课，晚上先心情）。
2. **记得，但别炫耀。** Everthine 和 Character.AI 都强调「真的记得」；Replika 的教训是记不住会让人心碎。莲花做法：把最近 6 条记录 + 今天未完成的日程压成两行摘要进系统提示，模型不用先调工具就知道「昨天念了 1080 声」；提示词同时要求「自然照应，不逐条复述，不每次都提」。
3. **别把用户的话弄丢。** SillyTavern 的 Edit / Regenerate 是角色聊天的标配，用户说错了、AI 答偏了都能原地修正而不用重来。莲花做法：消息悬停出现「复制 / 改一改 / 换一种说法 / 存为笔记」，编辑最后一条用户消息会从该处重新回复，换一种说法只对不含工具调用的最后一条回复开放（避免跳过已确认的写入）。
4. **让一句触动人的话有去处。** Character.AI 的 Pin to Memory、Mimir 的 cherish，都是「这句话我想留住」。莲花不建独立记忆系统，而是接到已有的笔记：「存为笔记」把回复原文带进记录表单，走同一套确认流程。
5. **不主动、不催、不留人。** Open-LLM-VTuber 与 Everthine 都有主动说话；Replika 因此出过伤害。莲花的承诺是「日程只有打开莲花时可见的到期提示」，所以做法是把**今天的日程**放在对话入口上方一条可关闭的小条，用户来了才看到，不发推送、不在对话里插话。

## 本轮落地清单（均经真实模型浏览器回归）

- 时段问候 + 起手句排序（`moment()`，单测锁定六个时段）
- 今日日程条（`TodayStrip`）：今天到期未完成、最多 3 条、可点开编辑/完成、可关闭到明天、过时的标「已过时间」
- 近况上下文（`recentContext()`）：实测模型不调工具直接答出「昨天念佛 1080 声，今晚 16:43 有晚课」
- 消息操作：复制 / 改一改（仅最后一条用户消息）/ 换一种说法（仅最后一条无工具回复）/ 存为笔记；触屏常显、桌面悬停
- 系统提示补「像常来往的道友：先接住状态再谈事；简短口语，多数时候两三句」

## 明确不做的（写下来防止以后走偏）

- 主动推送 / 定时问候 / 「你好久没来了」类召回文案
- 亲密度、好感度、等级、连续打卡天数——「不以记录数量判断功德」
- 消息评分、点赞训练——莲花不是在被调教的角色
- 情绪值、内心独白展示——容易变成表演，且法义回答必须有据可查
- 立绘、桌宠、虚拟形象——不是这个产品的问题

### 语音：原先一刀切写成「不做」，这是个归类错误（2026-09-16 修正）

早先把「语音」和「立绘、桌宠」并列划掉，混淆了两件性质完全不同的事。拆开后重判：

| 形态 | 判断 | 理由 |
| --- | --- | --- |
| **语音输入**（按住说话 → 转文字 → 走原有确认流程） | **应该做**，待排期 | 这是**无障碍需求不是陪伴功能**。念佛用户里年长者占比高，拼音打字是真门槛。转成文字后仍然经过用户确认才写库，工具审批边界一点不动。 |
| **语音朗读**（莲花把回答念出来） | 可做，但需产品先定调 | 对老花眼用户有价值；但给莲花一把人声会把它往「人」推，与「不培养依赖」的边界有张力。做的话应是**用户主动点播放**，绝不自动出声。 |
| **即时语音通讯**（实时双向通话） | **不做** | 两条硬理由：① 实时通话天然制造「对方在线等你」的压力，与「不打扰、不施加愧疚」直接冲突；② **工具审批流在语音里无法安全表达**——「记录念佛三千声」这种写库操作靠听觉确认极易误写，而每次写入必须经用户明确确认是莲花的底线。 |

技术现实（2026-09-16 实测）：

- 浏览器自带的 Web Speech API **在大陆不可用**——它把音频送到 Google 服务器识别，且微信内置浏览器不支持。这条"免费路"是堵死的。
- 我们**不需要新增供应商**：现用的硅基流动账号下已可见 `FunAudioLLM/SenseVoiceSmall`（`sub_type=speech-to-text`），中文识别，官方标称免费。
- ⚠️ 但本机**未能跑通实测**：同账号文本接口 0.57 s 正常、向中立 host 上传同样文件 8 s 正常，唯独该转写端点无论 217 KB / 65 KB / 12 KB、WAV / M4A 一律超时（75–120 s）。本机 TLS 代理对特定端点有已知异常，**因此不能据此判定服务不可用**，需换网络环境复测。
- 备选：Cloudflare Workers AI 的 Whisper，与现有部署同栈。
