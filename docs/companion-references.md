# 人机恋 / 陪伴类项目调研：小莲借鉴什么，不借鉴什么

调研日期：2026-09-15。目标是「小莲只有一个聊天入口」这一前提下，从 GitHub 上活跃的 AI 陪伴 / 人机恋项目里找**让人愿意每天回来聊**的交互细节。本次只读官方 README、文档与公开截图，没有安装或复用任何项目代码。

## 一句话结论

这些项目的黏性并不来自角色立绘或语音，而来自三件更便宜的事：**它知道现在几点、它记得你昨天说过什么、它不会把你的话弄丢**。这三件小莲都能在现有 Cloudflare Agent + 一个聊天入口的架构里做到，本轮已落地。亲密度等级、角色养成属于人机恋的养成机制，小莲不做；主动问候、情绪表达、记忆面板等其余各项不再一刀切排除，按 2026-09-16 的计划另行排期（见文末「边界」）。

## 从中提炼的五条原则

1. **知道现在几点，比知道你叫什么更重要。** KouriChat 的时间感知、Everthine 的早安消息、Yuralume 的作息，本质都是「对方活在和我同一条时间线上」。小莲做法：按北京时段变化的问候（夜深了 / 早安 / 午安 / 下午好 / 晚上好）、起手句顺序随时段调整（早上先功课，晚上先心情）。
2. **记得，但别炫耀。** Everthine 和 Character.AI 都强调「真的记得」；Replika 的教训是记不住会让人心碎。小莲做法：把最近 6 条记录 + 今天未完成的日程压成两行摘要进系统提示，模型不用先调工具就知道「昨天念了 1080 声」；提示词同时要求「自然照应，不逐条复述，不每次都提」。
3. **别把用户的话弄丢。** SillyTavern 的 Edit / Regenerate 是角色聊天的标配，用户说错了、AI 答偏了都能原地修正而不用重来。小莲做法：消息悬停出现「复制 / 改一改 / 换一种说法 / 存为笔记」，编辑最后一条用户消息会从该处重新回复，换一种说法只对不含工具调用的最后一条回复开放（避免跳过已确认的写入）。
4. **让一句触动人的话有去处。** Character.AI 的 Pin to Memory、Mimir 的 cherish，都是「这句话我想留住」。小莲不建独立记忆系统，而是接到已有的笔记：「存为笔记」把回复原文带进记录表单，走同一套确认流程。
5. **不催、不留人。** Open-LLM-VTuber 与 Everthine 都有主动说话；Replika 因此出过伤害。小莲目前的做法是把**今天的日程**放在对话入口上方一条可关闭的小条，用户来了才看到、不在对话里插话。主动问候（早安 / 晚安）2026-09-16 起不再一刀切排除，做的话要带次数上限（Everthine 每日 4 次的思路）且随时可关，属待排期项。

## 本轮落地清单（均经真实模型浏览器回归）

- 时段问候 + 起手句排序（`moment()`，单测锁定六个时段）
- 今日日程条（`TodayStrip`）：今天到期未完成、最多 3 条、可点开编辑/完成、可关闭到明天、过时的标「已过时间」
- 近况上下文（`recentContext()`）：实测模型不调工具直接答出「昨天念佛 1080 声，今晚 16:43 有晚课」
- 消息操作：复制 / 改一改（仅最后一条用户消息）/ 换一种说法（仅最后一条无工具回复）/ 存为笔记；触屏常显、桌面悬停
- 系统提示补「像常来往的道友：先接住状态再谈事；简短口语，多数时候两三句」

## 边界（2026-09-16 重划）

原先这里有一份「明确不做」清单（主动推送、亲密度、评分、情绪值、立绘、语音）。2026-09-16 决定去掉一刀切的限制，改为逐项判断：

- **仍不做**：亲密度 / 好感度 / 等级 / 连续打卡天数——这是人机恋的养成机制，与「不以记录数量判断功德」冲突；消息评分与点赞训练——小莲不是被调教的角色。
- **改为按需排期**（见 2026-09-16 计划「阶段 5」）：主动早安 / 晚安消息（要带次数上限、随时可关，且需要推送通道）、「小莲记得什么」的记忆面板、内心想法开关、立绘 / 形象类。
- **现在就做**：语音三种形态，见下。

### 语音：三种形态全做（2026-09-16）

| 形态 | 做法 | 写入怎么确认 |
| --- | --- | --- |
| **语音条**（按住说话、发出去、可回放、附转写） | 录音 → 客户端转 16 kHz WAV → Workers AI `whisper-large-v3-turbo`（`language: "zh"`）转写 → 走现有 `sendMessage`，原音存 R2 | 模型只看到转写文字，工具与确认卡一行不动 |
| **语音朗读**（小莲把回答念出来） | 助手消息上的「播放」键 → 中文 TTS → mp3，按消息缓存 | **只在用户点击时出声**，绝不自动 |
| **实时通话** | `agents@0.23` 的 `withVoice` 混入；STT 用 `WorkersAINova3STT({ language: "zh" })`（默认的 Flux 无中文）；TTS 需自写一个小 provider（melotts `zh` 待验，备选 SiliconFlow CosyVoice2 / ElevenLabs） | 通话里的写入工具不直接写库，改调现有 `createProposal`，小莲口头说「已放到对话里等你确认」，确认卡出现在聊天线程——**每笔写入仍由用户点按确认**。这就是原先「通话里审批无法安全表达」那条反对理由的答案 |

原先反对实时通话的另一条理由「制造对方在线等你的压力」仍然成立，所以通话必须由用户发起、随时可挂断，小莲不主动呼叫。

技术事实（2026-09-16 实测）：

- 浏览器自带的 Web Speech API **在大陆不可用**（音频送 Google 识别，且微信内置浏览器不支持），这条免费路堵死。
- 硅基流动账号下的 `FunAudioLLM/SenseVoiceSmall` 本机实测一律超时（75–120 s），而同账号文本接口与向中立 host 上传均正常——本机 TLS 代理对特定端点有已知异常，**不能据此判定服务不可用**。
- 因此语音条选 Workers AI Whisper（同栈、支持中文、$0.000513 / 分钟）；SenseVoice 留作换网络后的复测项。
- Deepgram Flux 于 2026-04 扩到 10 种语言，**没有中文**；aura-1 / aura-2 只有英语和西班牙语。这是通话不能用官方默认配置的原因。
